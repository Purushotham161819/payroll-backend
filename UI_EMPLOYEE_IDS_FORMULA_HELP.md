# Single PDF header, persistent employee IDs and compact formula help

## PDF presentation
Annual and Monthly PDFs now render only the main column-name header row. The secondary Component Code row is removed by returning a single header array in payrollPdfHead. Component codes remain stored in Salary Components and available in API/configuration metadata. Selected columns, user order, centered headers, right-aligned numeric values/totals, fonts, A4 landscape layout and downloads are preserved.

Employee IDs are shown in the existing Employee Name cell as EMP001 - First Last when available, avoiding any additional report column or changes to selection/order. Legacy responses without an assigned ID retain their existing name text. The directory never falls back to displaying MongoDB IDs; a legacy response temporarily shows ID pending instead.

## Persistent employee IDs
The additive employeeId field is generated by EmployeeIdentifierService. MongoDB _id remains the key for retrieval, editing, deletion, selection and internal references. Clients cannot supply employeeId through create/update DTOs; whitelist validation rejects those fields. The schema also marks employeeId immutable.

A dedicated employee_counters collection stores the employee sequence. An atomic findOneAndUpdate/$inc reserves each number; IDs use EMP plus a minimum of three digits (EMP001, EMP002, ..., EMP999, EMP1000). A database unique partial index on nonempty employeeId strings prevents duplicate persisted IDs. The counter is advanced using $max against the highest already assigned ID and is never reset or decremented after deletion. All application instances use the same database counter.

Reservations and employee writes are separate operations: failed creates, concurrent backfill attempts or deletions may leave gaps. IDs are unique and monotonic allocations, not a promise of gap-free numbering. No numeric part is derived from MongoDB _id or array positions.

## Existing employee assignment
An idempotent startup hook:
1. Audits already assigned IDs for canonical format/uniqueness, preserving them. Invalid/duplicate existing human IDs block startup rather than being overwritten.
2. Creates the additive unique index without dropping existing indexes or employee records.
3. Atomically advances/initializes the dedicated counter without lowering it.
4. Assigns IDs only to records whose employeeId is absent, null or empty, ordered by createdAt with _id only as a deterministic tie-breaker.

Each assignment is a conditional raw update. It preserves an assignment another process has already made, and it does not modify original createdAt/updatedAt timestamps, employee data, salary amounts or history. The hook runs on backend startup; new creates also await initialization. A partial failure can be retried after restart without reassigning completed IDs. Other writers must use this ID-generation path; directly inserted unidentified records are picked up by the next startup pass.

The implementation and backfill were tested against real MongoDB in uniquely named temporary databases. No explicit backfill command was invoked against payroll_db. Starting/restarting the updated backend applies the additive assignment to its configured database. No employee records, settings or history are deleted by this process.

## Formula help
The Build IF / ELSE button and builder-only state, handlers, template and styling are removed. The existing Annual Formula textarea remains, as do backend IF/MIN/MAX/percentage parsing, saved formulas, variable metadata and dependency resolution.

A subtle information button beside Annual Formula exposes a concise inline help panel with MIN, MAX and IF examples, comparisons, percentage literals, variable guidance and annual-first monthly behavior. It is hidden by default, keyboard-operable and labelled Formula help, with aria-expanded/aria-controls. It closes via its close button or Escape, does not overwrite the formula, and stays within the scrollable form on small screens. The app has no dedicated icon package; the button uses a simple information-symbol entity, consistent with its existing inline symbol convention.

The existing supported-variable registry remains available through a compact select-and-insert control. Custom component IDs remain in the existing collapsed reference details. No formula rules or statutory rates were changed.
