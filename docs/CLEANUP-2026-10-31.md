## Entry points and architecture reviewed

Backend: `src/main.ts` loads environment settings, creates `AppModule`, applies security and validation, then listens on the configured port. `src/app.module.ts` wires authentication, MongoDB, employees, salary components, payroll generator, Run Payroll and statutory deductions. Supporting boundaries include `organizations`, `income-tax`, `employee-tax-profile` and `tax-configuration`. DTOs, schemas, controllers, services, formula utilities, font assets and scripts remain in their original locations. Build uses `nest build`; Jest configuration limits test discovery to `src` and `test`. Production starts with `node dist/main`.

Frontend: `src/main.ts` bootstraps the standalone application using `src/app/app.config.ts`. That configuration provides guarded workspace/Super Admin routes, HTTP interceptors, lazy payroll/tax/settings features and Indian locale formatting. Existing `employees`, `payroll`, `features/run-payroll`, `features/tax-management`, `auth`, `platform`, `users`, `settings`, `shared` and `statutory-deductions` folders remain intact. Angular assets come from `public`; builds use the existing production configuration. Vitest runs through `ng test`; Playwright uses the existing Edge configuration.
